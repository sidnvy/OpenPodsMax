# OpenPodsMax 0.2.11

Optional rooted Apple Bluetooth identity, native AirPods handoff and automatic SBC are now included in the public Android release. No cloud account is required. Ordinary controls still work without root.

## Changes

- Add **About → Phone Bluetooth · Root → Apple Bluetooth identity**, off by default. Compatible rooted phones can advertise Apple Bluetooth Device ID without changing the Bluetooth MAC. The switch saves original values and supports restoration. KernelSU users may need to allow OpenPodsMax in their root manager and reopen the app.
- Support legacy Bluetooth Device ID configuration through a temporary runtime view, preserving signed system-file bytes. Refresh only the verified platform Bluetooth process to reload its cached Device ID. Enabling or restoring briefly disconnects all Bluetooth devices and is refused during playback or calls.
- Include the native AAP handoff responder developed with the Linux backend. Keep existing bond, audio-route, call and ownership guards.
- Add opt-in **Use SBC automatically** for the selected approved headset, using Android companion-device authorization. Reapply and verify SBC after connection; no root is needed for this feature.
- Include the experimental Linux Quick Toggle backend, installer/rollback and control recovery in source. Linux deployment and Bluetooth identity setup remain separate from installing the Android APK.

## Verified results

- **Owner listening PASS, 2026-11-13:** AirPods Max 2 switched seamlessly between the tested Linux laptop and Galaxy Z Fold8 using installed 0.2.11.
- **Independent identity/restore PASS:** fresh queries from Linux observed Apple `0x004C` → Samsung `0x0075` → Apple `0x004C` as the Fold switch was enabled, disabled and enabled again. The signed config remained unchanged. Same-key installation preserved SBC and playback preferences.
- Earlier Fold tests verified SBC after a real reconnect and AAC again with the opt-in disabled. These codec checks do not identify the AAC distortion's root cause.
- Earlier Moto/Linux tests covered audible bidirectional handoff with the existing setup and bonds. They are separate from the new Fold acceptance and do not validate Fold-to-Moto.
- Offline validation covers 22 property transactions, 16 legacy configuration/recovery cases, Android JVM and Python regressions, release compilation/lint and Linux backend/installer tests. Remote checks must pass on the tagged source before publication.

## Limits and recovery

Root compatibility is detected, not guaranteed for every rooted phone. Root identity is temporary for the current boot; while enabled, the app checks/reapplies it when next opened under safe audio conditions. It does not restart Bluetooth from boot. Existing bonds can cache identity; the app never deletes or recreates pairings automatically.

Disable the root switch to restore its saved values. If restoration is blocked, retain app data, restore root access or stop playback/calls, and use **Restore original identity**. Restore before uninstalling or clearing app data. See [root setup and recovery](../ROOT_BLUETOOTH_IDENTITY.md).

Fold-to-Moto switching, cold reconnect, Smart Case auto-connection and the new switch's reboot behavior remain unverified. The Linux integration still has documented suspend/reconnect limits. This release does not implement Apple Account/iCloud coordination, spatial head tracking or a universal seamless-switching guarantee. Experimental system Settings registration can still be reset by Bluetooth cycles or system updates.

## Updating and downloads

Official 0.2.x installations can update in place with the same release certificate; do not uninstall or clear data. Private/debug builds signed with another key cannot update in place and need a separate migration. The old Moto-specific identity preference does not silently enable the new global root switch.

Download `OpenPodsMax-0.2.11.apk` and `SHA256SUMS` together. Verify the checksum and release certificate using [release verification](../RELEASING.md). `BUILD-INFO.json` identifies the exact source commit, checks and hardware evidence. Linux users build from the tagged source and follow [Linux setup](../../linux/README.md); the APK does not install the Linux backend.
